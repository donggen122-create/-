## 1. 성능 목표 (측정 전 — "달성"이 아닌 "기준")

| 등급 | 대상 기기(예) | 해상도 | 동시 적 | 플레이어 투사체 | 파티클 | 프레임타임 목표 |
|---|---|---|---|---|---|---|
| PC 상 | 데스크톱 iGPU 이상, Chrome | 1920×1080 | 1,000 | 600 | 2,000 | p95 ≤ 16.7ms(60fps) |
| PC 하 | 저가 노트북 | 1280×720 | 600 | 400 | 1,000 | p95 ≤ 16.7ms |
| 모바일 상 | 최근 3년 플래그십 | 기기 해상도 ×0.75 | 400 | 200 | 600 | p95 ≤ 16.7ms |
| 모바일 중 | 중급기 | ×0.66 | 250 | 120 | 300 | p95 ≤ 33ms(30fps 허용) |
| 모바일 하 | 저가·구형 | ×0.5 | 150 | 80 | 100 | p95 ≤ 33ms |

- 등급은 첫 실행 시 3초 벤치(스프라이트 5,000 드로우) + UA 힌트로 자동, 설정에서 수동.
- 검증 씬: 성능 스트레스 도구(14장)로 등급별 상한 개체 + 보스 패턴 + 진화 이펙트 동시. **실제 측정 결과를 15장 부록에 기록하기 전까지 "달성"으로 표기하지 않는다.**

## 2. 최적화 기법과 규칙 불변 원칙

| 기법 | 내용 | 규칙 영향 |
|---|---|---|
| 객체 재사용 | 적·투사체·보석·파티클·피해 숫자 풀. SoA(Float32Array) 위치·속도·HP | 없음 |
| 공간 분할 | 2u 격자 해시. 충돌·조준·인력 질의 모두 격자 | 없음 |
| 화면 밖 | 렌더 컬링(시야+2u). 시뮬은 전체 유지. 30u 이상 적 재배치(규칙, 06장) | 규칙에 명시됨 |
| 보석 병합 | 300 초과 시 병합(값 보존) | 규칙에 명시됨 |
| 개체 상한 | 등급별 상한 + 대기열(개체 수 보존) | 생성 타이밍만 지연 |
| 파티클 제한 | 등급별 예산, 우선순위(진화·보스 > 사망 > 피격) | 없음 |
| 오디오 | 채널 16, 같은 SFX 50ms 중복 금지, 적 사망 초당 8 | 없음 |
| 효과 축소 옵션 | 3단계, 판정·수치 불변 | 없음 |
| 텍스처 | 아틀라스 2048² ×N, 적 스프라이트 64px 기준 | 없음 |
| 피해 숫자 | 화면 80개 상한, 텍스트 대신 비트맵 폰트 | 없음 |

판정은 항상 시뮬 데이터로만 계산하고 렌더 상태를 참조하지 않는다(효과 축소가 규칙을 바꾸지 않음의 근거).

## 3. 아트 제작 계획

### 3.1 개발 초기 대체 그래픽
- 캐릭터·적: 색상 원/사각 + 방향 삼각형 + 이름 라벨. 보스: 큰 다각형 + 패턴 예고 도형.
- 투사체: 단색 원·선. 장판: 반투명 원. UI: 시스템 폰트 + 단색 패널.
- 대체 그래픽은 `assets/placeholder/` 아틀라스 1장으로 제공되며 데이터의 `sprite_id`가 없으면 자동 사용.

### 3.3 제작 비용 원칙
- 05장 §5의 아트 공수(≈706 인일)는 위 표 기준. 이름만 있는 콘텐츠는 인정하지 않으므로 콘텐츠 추가 요청은 항상 아트 항목과 함께 백로그에 등록된다.
- 팔레트 스왑·스케일 변경은 "변형"으로만 취급하며 고유 수량에 넣지 않는다.
- 우선순위: 단계 1(15장 → 16장 개발 단계)에서는 대체 그래픽 100% → 단계 3에서 캐릭터 12·적 52·보스 20 → 단계 4에서 환경·UI 마감.
