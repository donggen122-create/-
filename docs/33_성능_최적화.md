# 성능 최적화 — 후반 난전에서 뚝뚝 끊기고 느려지는 것 (2026-09-24, Claude)

상태: 격리 서버에서 구현·측정 완료. 배포 여부는 STATUS 맨 위를 본다. 게임 규칙·보상·난이도는 바꾸지 않았다.
사용자 요청: "게임 최적화 좀 해줘. 뚝뚝 끊기거나 게임이 느려지는 현상이 최대한 없었으면 해". 이전 조사 메모: `docs/24_태블릿_렉_진단_메모.md`.

## 찾은 원인
1. **판이 길어질수록 계산이 느려졌다(가장 큰 원인).** 피해 숫자·맞음 효과 목록이 끝없이 쌓였다(진화 4개로 적 140마리와 싸우면 숫자 1,500~5,500개·맞음 효과 450~1,300개). 목록에서 하나씩 지울 때마다 뒤를 당겨 쌓일수록 제곱으로 느려짐. 같은 싸움에서 틱당 계산 10초 2.4ms → 60초 5.2ms(느린 태블릿이면 한 프레임 안에 못 끝남).
2. 스킬 탄 하나마다·틱마다 "살아 있는 적 목록"을 새로 복사(쓰레기 → 잠깐 멈춤).
3. 적마다 모든 소품(장애물)과 거리 계산(제곱근).
4. 그리기: 적 정화 효과의 반짝이 6개를 하나씩 칠함, 효과를 64~96개까지 겹쳐 그림, 글자마다 글꼴 해석·저장/복원, 거의 안 보이는 격자선 40여 개.
5. GPU 길: 미리 만들어 둔 **캔버스**(테마 효과 그림·색조/번쩍임 적·빛 번짐·가장자리 어둡게)를 그림처럼 그리면 매번 GPU로 다시 올린다(측정: 같은 수의 일반 그림보다 약 100배). 고해상도 적 그림(약 160px)을 매 프레임 40~70px로 줄여 그림.

## 고친 것
| 곳 | 내용 |
|---|---|
| `main.js` | 피해 숫자 90개·맞음 효과 120개·정화 효과 120개까지(오래된 것부터 버림, 진화·보상 안내 글은 남김). 그리는 개수 맞음 32·정화 32(전 96·64). 숫자 그리기는 한 번 훑고 글꼴·테두리는 묶음마다 한 번, 글자마다 setTransform. 장애물은 단단한 소품만 틱마다 한 번 추리고 먼 것은 제곱근 없이 넘김. 환경 테마 바닥 위 격자선 생략. 고해상도 적 그림은 화면 픽셀 크기로 한 번 줄여 둔 사본(`scaledSprite`, ImageBitmap)으로. 가장자리 어둡게도 ImageBitmap |
| `element-combat.js` | 살아 있는 적 목록을 틱마다 한 번(이 모듈 공격으로 적이 쓰러지면 다시), 탄 충돌은 멀리 있는 적을 먼저 거름 |
| `element-effects.js` | 빛 번짐 캐시를 ImageBitmap으로 |
| `theme-effects.js` | 효과 그림 캐시를 ImageBitmap으로, 반짝이는 한 번에 칠함, 움직임 줄이기 설정은 한 번 읽어 둠 |
| `assets.js` | 색조·번쩍임 스프라이트 캐시를 ImageBitmap으로 |

## 측정(격리 서버, 헤드리스 Chromium — 소프트웨어 그리기라 비교용)
- 도구: `game/tools/qa/bench.py`(같은 판에서 계산 5초·같은 장면 60번 그리기 9번 중앙값), `game/tools/qa/perf.py`(실제 시간·CPU 느리게·함수별 시간, `--gpu`), 게임 속 `__debugBench`·`__debugPerf`(로컬 전용).
- 난전: 2-3, 진화 4개(화산·왕 물풍선·천둥·태풍) + 범위 최대, 적 약 160마리(측정 중 쓰러지지 않게).

| 틱당 계산 | 전 | 후 |
|---|---|---|
| 태블릿 1180(배율 2) | 1.83~3.48ms | 0.77~0.84ms |
| 폰 375(배율 3) | 1.67~1.89ms | 0.80~1.03ms |
| PC 1280 | 1.30~1.78ms | 0.79~0.83ms |

| 같은 싸움 60초(PC) | 10초 | 30초 | 60초 |
|---|---|---|---|
| 전: 틱당 계산 | 2.42ms(숫자 1,550) | 4.38ms(숫자 2,697) | 5.19ms(맞음 효과 798~1,286) |
| 후: 틱당 계산 | 0.95ms(숫자 90) | 1.00ms | 0.97ms |

- 그리기(한 번당): 헤드리스 소프트웨어 그리기에서는 전후 차이가 측정 흔들림(±10%) 안이다(태블릿 72~80 → 65~76ms, 폰 37~42 → 33~41ms). 소프트웨어 그리기는 칠하는 픽셀 수가 대부분이라 그렇다. ImageBitmap·줄인 사본은 실제 기기의 GPU 그리기에서 효과가 나는 고침이라 여기서는 확인할 수 없다.
- 실제 기기에서 확인할 것: 태블릿으로 2장 후반(진화 3~4개)까지 해 보고 끊김이 줄었는지.

## 알아 둘 것
- 보이는 모습: 한꺼번에 수십 마리가 쓰러질 때 정화 효과·맞음 효과가 최근 32개까지만 그려진다(같은 자리에 겹쳐 차이가 거의 없음). 피해 숫자는 그대로 최근 40개(폰 20개).
- 화질 자동 조절(느리면 해상도 2 → 1.5 → 1.25 → 1)은 그대로.
- 측정용 훅(`__debugPerf`·`__debugBench`, `qaRatio`)은 로컬(localhost)에서만 켜진다.
