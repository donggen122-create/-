# Codex 작업 지시 — 태블릿 렉 2차: 적이 많을 때의 계산(이동·충돌·거리) 줄이기 (2026-10-08, Claude → Codex)

선생님: "남은 렉도 더 잡어." 1차(`docs/codex/2026-10-08_보고_태블릿_렉.md`, 커밋 c1101d4~e47acf2, Claude 검토 9b313a0)는 그리기 쪽을 줄였고 거품 장면만 뚜렷이 좋아졌다. 가장 무거운 조건(4-3 적 160마리, CPU ×6)은 여전히 초당 9~10장이다. 이번에는 **계산(sim) 쪽**이다.

## 0. 지킬 것 (1차와 같음 + 더 엄격히)
- 먼저 읽기: 1차 보고서 전체(특히 "느린 장면의 함수 상위 10개", "결과 판단과 다음 순서", "남은 위험"), `CLAUDE.md`, `game/STATUS.md` 맨 위.
- **push 금지, 배포 금지, `main` 금지, 실서버·실제 D1 접속 금지.** 로컬 `seoho-game`에 커밋만. push는 Claude가 검토 뒤에 한다.
- **판 결과는 한 비트도 바뀌면 안 된다.** 같은 시드·같은 조작·같은 틱이면 적 위치·넉백·피격·처치 순서·난수 소비 순서·정산이 전과 같아야 한다. "거의 같다"는 통과가 아니다.
  - 공간 격자 등으로 후보를 줄일 때는 **후보 집합이 원래 검사에서 실제로 걸리던 대상을 모두 포함**하고, **처리 순서가 원래 배열 순서와 같아야** 한다(격자에서 꺼낸 뒤 원래 인덱스 순으로 처리).
  - 결과를 똑같이 유지할 수 없는 최적화는 **넣지 말고** 보고서에 "효과 예상치 / 결과가 달라지는 이유 / 밸런스 재확인에 필요한 것"만 제안으로 쓴다.
- 눈에 보이는 모습도 PC 기본 화질에서는 그대로(1차의 PC 픽셀 비교 유지).
- 1차에서 만든 도구(`game/tools/qa/tablet-perf.py`, `tablet-summary.py`)와 저장소 밖 venv(`%LOCALAPPDATA%\seoho-qa-venv`)를 그대로 쓴다. git 설정은 바꾸지 않는다.

## 1. 대상 (1차 trace 순위 그대로 — 먼저 다시 재서 확인)
4-3 군중 iPad급 ×6 (15초 self ms, 1차 "후"): `updateEnemies` 466 · `moveEnemy` 376 · `resolveObstacles` 351 · `dist`(element-combat) 306 · `simTick` 238 · element-combat 익명 함수(281·106행 근처) 200+150 · `skillDamageMultiplier`(rework-core) 192 · `updateShots` 136 · `stepToward` 125.

확인할 후보(짐작 — 재서 맞으면 고친다):
- `updateEnemies`/`moveEnemy`의 적끼리 밀어내기·겹침 검사가 n×n이면 → 공간 격자(결과·순서 동일 조건).
- `resolveObstacles`: 적마다 모든 장애물(decor solid)을 훑으면 → 장애물은 거의 안 움직이니 격자/칸 목록을 판 시작 때(또는 바뀔 때만) 만든다.
- element-combat의 `alive().filter(...dist...)` 반복: 스킬·투사체마다 전체 적을 훑는 범위 검사 → 격자 후보 + 원래 순서. `dist`는 `Math.hypot`인데, 반지름 비교만 하는 곳은 값이 정확히 같은 판정이 되는 범위에서만 바꾼다(부동소수점 경계에서 판정이 달라지면 안 됨 — 확신이 없으면 hypot 유지).
- `skillDamageMultiplier(profile,id)`가 매 타격마다 다시 계산되면 → 판 도중 profile이 안 바뀌는 구간에서 캐시(바뀌는 시점에 반드시 무효화, 값 동일).
- 틱마다 새 배열·객체를 만드는 `filter`/`map`/스프레드 → 재사용 버퍼(순서 동일).
- `rework-core.js`는 서버도 쓰는 규칙 파일이다. **값·규칙을 바꾸지 말 것.** 꼭 필요하면 호출하는 쪽(main.js·element-combat.js)에서 캐시한다.

## 2. 측정 (잡음에 속지 않게)
1차는 15초 한 번씩이라 ±1.5 FPS가 잡음이었다(Claude 재측정: 4-3 군중 iPad ×4 전 16.7·17.5 / 후 17.9·16.1).
- 전/후를 **번갈아**(전·후·전·후…) **각 3번 이상** 재고 **중앙값과 최소~최대**를 함께 쓴다. 범위가 겹치면 "차이 없음"이라고 쓴다.
- 기준(전) = 지금 HEAD(`--source 9b313a0` 또는 해당 커밋), 후 = 작업본.
- 장면: 4-3·4-5·4-4 군중(`--stress`) × iPad급·안드로이드급 × CPU ×4·×6, 그리고 자연 후반 4-3·3-3 iPad ×4(회귀 확인).
- 핵심 지표는 **프레임당 계산 시간(sim ms)** 과 평균 FPS·하위 1%·>50ms 비율. trace로 상위 10개 함수 전/후.
- 측정 중에는 다른 무거운 작업을 돌리지 않는다. 다른 프로세스가 CPU를 쓰는 게 보이면 그 표본은 버리고 다시 잰다.
