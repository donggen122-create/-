# 서호팡팡수호대 — 1-1~1-5 실제 구현 인수인계

2026-09-22. 이 문서는 이번 개편의 구현 기준이다. 과거 30단계 원안과 CSV는 보관 자료이며, 이번 서비스 범위는 첫 마을 5단계다. 기존 기획·구현 요청 패키지보다 이 문서와 실제 소스를 우선한다.

## 적용한 경험

- PC: WASD/방향키. 모바일: 화면을 끌어서 이동. 공격은 자동이다.
- 로비는 모험·친구·장비·도감·선물 다섯 탭이다.
- 전투는 공격 도구 3칸, 도움 2칸이다. 도구 3단계 + 짝꿍 도움 1단계를 모으면 자동 합체한다. 카드 선택 중 시간은 멈춘다.
- 1-1·1-2는 처음 성공할 때까지 3분, 이후 반복 도전과 1-3·1-4는 5분이다. 1-5는 4분에 보스가 등장하며 6분 안에 구출한다. 편안하게/보통은 보상이 같다.
- 코인 강화는 실패하지 않는다. 도구·옷·신발 칸을 강화하므로 장비를 바꿔도 강화가 유지된다. 같은 장비 3개/7개는 반짝/무지개로 자동 성장한다.
- 물방울·바람·새싹 세트는 2개/3개 효과가 있다. 이동 속도 보너스는 최대 15%다.
- 동물 친구 6종은 줍기·방패·물방울·밀기·치료·범위 공격 역할을 갖는다. 함께한 우정으로 모두 같이 성장하며 먹이·배고픔·친구 사망은 없다.
- 1-2 집게, 1-3 첫 친구 선택, 1-4 씨앗, 1-5 새싹 도구·새 친구 선택·선물 상자가 열린다.
- 선물표와 이용권은 서로 다른 자원이다. 선물은 다섯 번째마다 직접 고를 수 있다. 유료 결제·광고·이용권 보상은 없다.
- 기본 장비 없이도 첫 마을을 진행하도록 맞췄다. 이후 2~6장, 새로운 도구 3종은 이번 범위에 포함하지 않으며 잠금 안내만 보인다.

## 이용권 정책 — 서버가 최종 결정

한국 시간 매일 오전 8시에 기본 이용권이 **10장**이 된다. 이월·시간 충전은 없다. 성공 결과를 서버에 저장할 때 1장 사용하고 실패·중도 종료는 0장이다. 0장이면 새 도전을 시작할 수 없다. 실패 횟수는 제한하지 않으므로 이 정책은 **하루 기본 성공 10회** 제한이다.

로비 이용권을 누르면 위 정책과 현재 기본/관리자 추가 수량을 읽을 수 있다. 오전 8시를 넘겨 성공한 도전은 성공한 날의 이용권을 쓴다. 로비에서는 15초마다 서버 상태를 갱신한다.

관리자 추가분은 기존 `/admin/`의 열쇠 인증을 통과한 서버 API로만 지급한다. 학생 계정에 관리자 역할을 추가하지 않았다. 추가분은 기본 10장을 먼저 사용한 다음 소모하고 다음 오전 8시에 만료한다. 개별·전체 지급과 최근 지급 기록 API가 있다. 관리자 비밀 값은 소스·문서·리소스에 포함하지 않는다.

일일 미션·출석·선물·옛 에너지 API·학생 저장 업로드로 이용권을 늘릴 수 없다. 옛 저장 PUT과 에너지 지급 API는 410으로 종료된다. 동시 실행은 계정당 한 판, 중복 결과는 같은 결과를 돌려주며 재차 차감하지 않는다. 끊긴 저장은 같은 요청 번호로 재확인한다.

## 기존 계정 이전

첫 개편 접속 때 새 `guardian_profiles`를 한 번 만들고 이전 `saves` 행은 수정하지 않는다. 기존 로그인/비밀번호/잠금 상태도 유지한다.

- 금화는 코인 1:1, 단계 성공·별·최단 기록·선택 주인공·누적 판 수는 보존한다. 과거 별의 불리언 배열과 숫자 형식을 모두 받는다.
- 이전 6부위는 새 3칸으로 정리한다. 무기·목걸이·장갑→도구, 갑옷·허리띠→옷, 신발→신발이다.
- 이전 세트 01/04/07→새싹, 02/05/08→바람, 03/06→물방울이다. 이전 등급 0~1/2~3/4~5는 각각 1/3/7개로 환산한다. 7개 초과분은 개당 60코인이다.
- 이전 장비 강화에 사용한 금화는 기존 공식대로 환급하고 새 칸 강화는 1단계에서 시작한다. `migration.upgradeRefund`로 확인한다.
- 이전 친구는 역할별 새 친구로 옮기며 최고 친구 레벨을 공통 우정에 반영한다. 구체적 ID 매핑은 migration 파일에 있다.
- 특성·수집품·파츠·다른 재화 등 이번 화면에서 제외된 체계는 이전 저장에 보관한다. 새 전투에는 영향을 주지 않는다. 이 자산들은 아직 새 체계로 전부 환산한 것이 아니다.
- 관리자 진행 초기화도 당일 이용권 사용량을 복구하지 않는다. 별도 추가 지급이 필요하다.

## 실행·검증·배포

Node 24 기준이다. 처음 한 번 `cd server && npm ci`를 실행한다. 저장소 루트에서 `npm run build`, `npm test`를 실행한다. 로컬 D1은 `cd server && npm run db:init:local`, 서버는 `npm run dev`이다. 별도 터미널의 루트에서 `node tests/http-integration.mjs`를 실행한다.

로컬 시험에만 `server/.dev.vars`를 만들 수 있다. `ADMIN_KEY="local-only-test-key"`, `LOCAL_TEST_CLOCK="true"`는 로컬 시험값이며 배포 설정에 절대 추가하지 않는다. 운영에서는 실제 경과 시간이 부족한 성공을 거절한다. 클라이언트 디버그 도구도 localhost에서만 정의된다.

운영 D1에 `schema.sql`을 다시 적용할 필요가 없다. 새 API 최초 호출에서 `guardian.js`의 추가 전용 스키마를 D1 바인딩으로 적용한다. 기존 users/saves를 교체하지 않는다. 기존 `ADMIN_KEY` Worker secret을 유지한다.

배포 직전 `npx wrangler deployments list`로 타 작업의 새 변경이 없는지 확인한다. 이번 소스는 운영 버전 `2d5019e0-8b9e-4547-b63a-b9e68aa402ce`의 Worker/관리자/공유 문서와 전투 VFX를 확인·병합한 기반이다. 서버 폴더에서 `npm run deploy`를 실행한다.

되돌릴 때는 해당 배포 버전으로 Worker와 정적 파일을 함께 롤백한다. 새 테이블은 추가만 되었으므로 남겨 둬도 되지만, 이전판으로 돌아가면 개편 이후 성장 내역은 이전 게임에 표시되지 않는다. 학생의 원본 저장과 새 프로필을 삭제하지 말 것.

## 검증 범위와 남은 확인

규칙 단위 검증, 로컬 Wrangler/D1 HTTP 경합 검증, 실제 Chrome의 첫 5단계 성공·해금·친구 선택·강화·다섯 번째 선물 선택을 확인했다. 390×844 모바일 화면에서 탭·안내문·터치 드래그를 확인했다. 결과 저장 응답을 끊은 뒤 새로고침해도 한 번만 반영되는 것을 시험했다.

단순 이동 봇으로 무적 없이 1~5단계를 완료했으나 이는 실제 학생 성공률의 증거가 아니다. 실제 저사양 학생 기기 성능, Safari/iOS, 1~6학년 학생별 체감 난이도와 장기 반복 재미는 교실 시범 플레이가 필요하다. 브라우저 전투 결과 자체를 서버에서 재현하는 완전한 부정행위 방지까지 구현한 것은 아니다. 서버는 진행 해금·실제 최소 시간·보상 수치·이용권·중복 저장을 검증한다.

다음 조정은 `rework-content.js`의 적 밀도·보스 수치와 `rework-core.js`의 보상/강화 비용부터 한다. 과거 CSV를 수정해 새 게임에 자동 반영될 것으로 가정하지 말 것.
