## 1. 결과 검증 강화(먼저)
- 먼저 **성공 조건을 확인**해 보고서에 적어라: `guardian.js` 정산은 성공 시 `seconds ≥ duration−3`을 요구하므로 "가장 빠른 성공 시간"은 모든 성공이 거의 같아 **순위 기준이 못 된다**(확인하고 다르면 보고). 그래서 순위 기준은 3절의 처치 수다.
- 규칙 표는 한 곳 `server/src/anomaly.js`: 단계별 **처치 수 상한**(= 그 단계의 생성 속도 × 제한 시간 × 1.5 — `rework-core.js`의 단계 수치에서 **계산**하고, 자동 조종(`game/tools/qa/sim.ps1` 또는 `tablet-perf.py`) 실제 최대값과 비교해 상한이 실제 최대의 1.3배 이상인지 확인), 쓰레기 수 상한(단계 목표 × 2, 지금 99 유지), 시간 범위, 대왕 단계 `bossSeconds` 필수·범위, `hpFraction` 0~1, 성능 요약과의 모순(예: 평균 FPS 0인데 처치 최대).
- 결과: `result.flags:[{code, value, limit}]` 기록(없으면 생략) + `play_runs`에 `flagged INTEGER DEFAULT 0` 열(마이그레이션). **보상 보류는 "불가능한 값"(상한의 2배 초과)일 때만**: 보상 0으로 정산하고 `result.held=true`, 학생 화면에는 "기록 확인 중" 한 줄(비난 표현 금지). 나머지 깃발은 기록만(보상 정상).
- 관리 페이지 **"이상 판"** 목록: 학생·단계·까닭(깃발)·시각·보류 여부. 최고 관리자만 "보상 지급"(보류 해제 — 그 판 보상을 지급) / "그대로" 단추. API `GET /api/admin/anomalies`, `POST /api/admin/anomalies/release`.

## 2. 닉네임
- `users`에 `nickname TEXT`, `nickname_status TEXT NOT NULL DEFAULT 'none'`('none'|'pending'|'approved'|'rejected'), `nickname_set_at INTEGER`, `nickname_note TEXT`(거절 사유). 마이그레이션 파일 + `schema.sql` 갱신 + **서버가 열이 없는 DB에서도 죽지 않게**(첫 요청 때 `PRAGMA table_info(users)`로 없으면 `ALTER TABLE ADD COLUMN` 자동 적용 1회 — 기존 `guardian.js`의 `CREATE TABLE IF NOT EXISTS` 방식과 같은 자리에서).
- 학생: 랭킹 화면에서 닉네임 입력(2~8자, 한글·영문·숫자만, 앞뒤 공백 제거) → `server/src/banned-words.js` 검사(욕설·비하·성적 표현·"선생님"·"관리자" 등 사칭어·아이디와 같은 값 금지; 성+이름처럼 보이는 한글 3글자는 **경고만**: "실명은 쓰지 않는 게 좋아요") → 통과하면 `pending`. 바꾸면 다시 `pending`. `POST /api/nickname`.
- 선생님 관리 페이지: 대기 목록(아이디·요청 닉네임·시각) 승인/거절(사유 한 줄). `GET /api/admin/nicknames`, `POST /api/admin/nicknames/decide`.
- 표시 규칙(모든 학생 화면 공통 함수 `displayName(user)`): `approved` → 닉네임, 그 외 → "수호대원 ○○"(아이디에서 **유추 불가능한** 익명 번호: 서버가 user id의 해시 앞 2자리 숫자 등, 매번 같게).

## 3. 랭킹(`GET /api/ranking`, 로그인한 학생)
- **이번 주 단계**(KST 월요일 00:00 시작, 주 키 `YYYY-Www`): 상수 `WEEKLY_STAGES` 순환 — 순서 **1-3 → 2-3 → 3-3 → 4-3 → 1-5 → 2-5 → 3-5 → 4-5**(늦게 시작한 학생도 앞 주에 기회) + 관리 페이지에서 **이번 주 단계 바꾸기**(설정 표 `settings(key, value)` 1행; 선생님 가능).
- 기준: 그 단계 **한 판 최고 처치 수**(성공 판만, 이번 주에 정산된 판만; 동점이면 쓰레기 수, 그다음 먼저 기록한 사람). 시험 계정(`TEST_ACCOUNT_RE`)·보류 판(`held`)·불가능 깃발 판 제외.
- 화면: **1~10등**(표시 이름 규칙 2절) + **내 순위·내 기록**(10등 밖이어도). 11등 이하 명단은 보내지 않는다(꼴찌가 드러나지 않게 — 학생 걱정).
- **명예의 전당**: 대왕 단계(1-5·2-5·3-5·4-5) 각각 정화한 모든 학생(표시 이름, 순위 없음, 가나다 순, 승인된 닉네임만 — 익명 번호는 "그 외 n명"으로).
- **칭호**(능력 없음, 표시만, `ranking.js` 한 표): "쓰레기 마을 수호대"(1-5 정화) · "공장 지대 수호대"(2-5) · "오염된 하천 수호대"(3-5) · "불타는 숲 수호대"(4-5) · "이번 주 1등"(지난주 1위 — 그다음 주 동안) · "첫 출동"(판 1회). 학생은 가진 칭호 중 하나를 골라 이름 옆에 표시(`users.title` 열 또는 프로필 안 — 프로필 형식을 바꾸지 않는 쪽: `users` 열).
- **전교 협동 목표**: 이번 주 전체 성공 판 수 합 / 목표(상수 `WEEKLY_GOAL`, 기본 300; 설정 표로 바꿀 수 있게) 진행 막대 + "우리 모두 n판 정화!" — 표시만, 보상 없음.
- 화면 위치: UI 2 로비 **모험 탭 제목 줄 오른쪽(오늘의 미션 옆)에 "랭킹" 단추** → 모달(탭 4개: 이번 주 순위 / 명예의 전당 / 내 칭호·닉네임 / 협동 목표). UI 1은 같은 모달을 머리글 단추로. 폰 375×667에서도 깨지지 않게. 출동 단추 검사(`responsive-audit.py`의 출동 단추 항목)가 깨지지 않게.
- 성능(D1 읽기): 주간 순위는 `play_runs`를 **이번 주 범위만**(`settled_at` 색인 — 없으면 마이그레이션으로 추가) 읽고 결과를 **60초 메모리 캐시**(Workers isolate 안, 키 = 주 키+단계). 학생 100명·하루 1,000판 기준 요청당 쿼리 수·읽은 행 수를 보고서에.
