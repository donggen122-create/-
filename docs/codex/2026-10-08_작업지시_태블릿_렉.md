## 1. 상황 파악(측정)
1. **실제 기록 확인**: 지금 판 기록에 성능 정보(fps 등)가 남는지 서버·클라이언트 코드에서 확인(Claude가 본 바로는 없음). 있으면 D1에서 기기 종류별로 집계.
2. **태블릿 재현**(격리 서버, Playwright/CDP): 기기 3종 — iPad급 1180×820 @2x, 보급형 안드로이드 태블릿 1280×800 @1.5x, 세로 820×1180 @2x — × CPU 느리게(`Emulation.setCPUThrottlingRate` 4배·6배).
   장면: 1-5 대왕, 2-5, 3-3(거품), 3-5, 4-2(톱니), 4-3(불도저), 4-4(불키), 4-5(산불 거인) — 각각 **판 후반**(자동 조종으로 7~9분, 스킬 진화·적 최대).
   또 **여러 판 연속**(같은 탭에서 5판) — 판을 거듭할수록 느려지는지(메모리·이벤트·타이머 누수).
   로비: UI 1 ↔ UI 2 탭 전환·스크롤 반응 시간.
3. 기록: 평균 fps, 하위 1% fps, 33ms·50ms 넘는 프레임 비율, 프레임당 계산(update)·그리기(draw) 시간, 캔버스 실제 픽셀 수, 적·투사체·효과·숫자 개수 최대, 해상도 단계 변화, 판마다 메모리(heap).
4. 가장 나쁜 장면 2~3개는 성능 기록(trace)을 떠서 **오래 걸리는 함수 상위 10개**를 뽑는다.

## 2. 최적화(1절 숫자로 효과가 큰 것부터)
확인할 후보(짐작 — 재서 맞으면 고친다):
- 캔버스 해상도: 태블릿 @2x면 픽셀 4배. 느린 기기 해상도 단계가 제때 내려가는지·오르락내리락하지 않는지.
- 매 프레임 새 배열·객체(`filter`/`map`/`sort`), 매 프레임 그라디언트·`shadowBlur`·`filter`·큰 반투명 화면 덮개(거품·불 구역·안개), 큰 그림을 매번 줄여 그리기 → 미리 만든 그림(ImageBitmap)·묶어 그리기.
- 충돌 검사 n×n → 칸 나누기(공간 격자).
- 매 프레임 DOM 쓰기(HUD 글자·막대) → 바뀔 때만.
- 소리: 맞을 때마다 새 오디오 노드 → 동시에 나는 소리 수 제한.
- 판이 끝나도 남는 타이머·리스너·배열(연속 판에서 느려짐).
- 로비(UI v2): 큰 `filter: blur()`·`backdrop-filter`·큰 그림자·무한 애니메이션 → 미리 흐리게 만든 그림, 애니메이션 줄이기(느린 기기·움직임 줄이기 설정).
- 4장 새 행동(`sgT4Tick`, 불 구역, 바퀴 자국)과 3장 거품의 그리기 비용.

## 3. (선택) 실제 학생 기기 성능 기록
