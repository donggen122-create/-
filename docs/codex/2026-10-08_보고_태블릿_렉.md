## 결과 판단과 다음 순서

- 가장 분명한 개선은 연속 거품: 평균 FPS 약 35% 증가, >50ms 5.7→0.4%. 고정 그림 완료 시간은 3-3 약 21%, 4-3 약 16% 줄었다. 연속 5판 FPS도 전후 모두 따로 확인했다.
- 군중 12조합은 평균 FPS가 9조합에서 증가하고 3조합에서 감소했다. 악화는 iPad급 ×4 4-3, 안드로이드급 ×6 4-3, 세로 ×6 4-5다. 자연 장면의 1-5·3-5 하위 1%도 낮아졌다. **모든 장면이 개선됐거나 렉이 해결됐다는 결론은 아니다.** 한 번의 15초 표본이라 작은 차이를 확정적 효과로 해석하지 않는다.
- 거리 함수의 self 시간은 군중 4-4에서 244→171ms, ×6 4-5 trace에서 375→249ms로 줄었지만, ×6 4-3은 326→306ms로 차이가 작았다. 남은 적 갱신·이동·장애물 처리가 상위에 남는다(4-3 후: `updateEnemies` 466ms, `moveEnemy` 376ms, `resolveObstacles` 351ms). 프레임마다 해야 하는 계산과 native raster/대기 때문에 부분 비용 감소가 FPS에 그대로 이어지지 않는다.
- 다음은 실제 태블릿에서 특히 4-3 후반을 재고, 적 이동/장애물 충돌의 공간 검색을 기존 적·장애물 순서와 같은 판정으로 줄일 수 있는지 확인하는 작업이다. 변경한다면 좌표·넉백·동점·피격·정산의 시드 재생 범위를 더 넓혀야 한다. 이번에는 이 검색 규칙을 교체하지 않았다.
- 연속 5판의 리스너는 전후 93개, 남은 interval 2개·timeout 0개였다. 마지막 JS heap도 약 6.76→6.75MB로 비슷했다. 초기 대비 증가분과 native/GPU 메모리는 남아 있으므로 장시간 누수 부재를 주장하지 않는다.

## 선택 기능과 남은 위험

- 학생 기기 성능 수집(선택 3절)은 구현하지 않았다. 서버 변경·실기기 검증 범위를 늘리지 않기 위해 제안으로 남긴다. 다음 단계에서 결과 JSON 안에 버전, 평균/하위 1% FPS, 긴 프레임 비율, 화질, tablet/phone/PC와 화면 크기 구간만 추가하고 서버에서 유한수·상한·필드 허용 목록·JSON 크기(예: 1KB 이하)를 검사한다. 새 표·전체 UA·개인 식별 정보는 필요 없다. 이 작업도 Claude 검토와 별도 실기기 확인이 필요하다.
- 실제 iPad/Safari·보급형 안드로이드 GPU, 오디오 체감, 학생 입력 지연, 브라우저 배경 복귀는 미확인이다. ImageBitmap resize 미지원이면 안전하게 원본으로 돌아가지만 그 환경의 속도 개선은 미확인이다.
- 합성 군중의 CPU ×6은 개선 후에도 느릴 수 있다. 이동·장애물·충돌 비용은 남아 있다. 바퀴 자국/불 공 시험은 합성 시각 부하이므로 실제 발생 빈도와 같다고 해석하지 않는다.
- 연속 5판은 15초 창과 빠른 후반 이동을 사용한 짧은 검사다. JS heap 이외의 native bitmap/GPU 메모리와 수업 한 시간 규모의 누수는 검증하지 않았다. 캐시 개수 상한·닫기 검사는 메모리 누수 부재의 증명이 아니다.
- 판 결과 비교는 같은 60Hz 틱·조작·draw 호출 순서에서 수행했다. 기존 `draw()`의 화면 흔들림이 `Math.random`을 게임 계산과 공유하므로, 서로 다른 실제 FPS에서 난수 소비 순서까지 같다고 보장하는 검사는 아니다. 이를 분리하면 기존 시드 결과를 바꿀 수 있어 이번 수정에 넣지 않았다.
- 동일 결과 검사의 1-5는 정상 승리 정산, 나머지는 약 275초 시점의 전체 판 통계와 QA 중도 종료 정산을 비교한다. 모든 장면의 정상 승리까지 검증한 것은 아니다. PC 픽셀 비교 대상은 게임 캔버스이며 로비 전체 화면의 픽셀 비교는 수행하지 않았다.
