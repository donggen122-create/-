## 1. 먼저 재기 (고치기 전)
격리 서버에서 Playwright로, 캐시 없는 새 브라우저 문맥으로:
- 시작 화면이 다 뜰 때까지 **요청 수·받은 바이트**를 폴더별(`src`, `assets/sprites`, `assets/elements_v2`, `assets/ui`, `assets/ui2`, `assets/seoho_v1`, `assets/audio`)로. PC 1280×720, 폰 375×667, iPad급 1024×768(CPU ×4).
- 로그인 → 로비까지, 로비 → 1-1 출동 → 전투 첫 프레임까지 각각 추가로 받은 양과 걸린 시간.
- 두 번째 접속(같은 문맥에서 새로고침)에서 받은 양(지금 캐시가 얼마나 도는지).
- Claude가 PC 1280×800에서 본 값: 시작 화면 21.4MB / 250개(스프라이트 10.0MB, 소리 3.7MB, 원소 효과 2.9MB, UI 3.6MB, 코드 1.3MB).

## 2. 장별 분할 로딩 (1단계 ①)
목표: **1장만 하는 학생은 4장 그림과 소리를 받지 않는다.**
1. 시작 화면: 시작 화면에 보이는 것(배경·엠블럼·호야·민지 응원 포즈·마스코트·UI)만.
2. 로비: UI 2 아이콘·장 카드 작은 그림·친구 idle·장비 아이콘 등 로비에 보이는 것. 주인공 전투 프레임은 **고른 주인공 것만**.
3. 전투: **출동을 누를 때** 그 장의 적·바닥·소품·효과(`t1~t4`, 대왕 효과)와 원소 효과(`elements_v2`, 공통이면 첫 출동 때 한 번)를 받는다. 받는 동안 출동 단추에 "불러오는 중 ○○%"를 보이고, 다 받은 뒤 판을 시작한다(판 시작 뒤에 그림이 늦게 나타나는 일이 없게). 한 번 받은 장은 다시 받지 않는다.
4. 그림 목록은 코드로 만든다(`assets.js`의 스프라이트 표를 장별로 나누기 — 이름 규칙 `t1_*`… 으로 묶을 수 있으면 그것으로). 빠진 그림이 있으면 전투 중에 보이지 않으므로, **장마다 모든 적·대왕 기술·소품이 그 장의 목록에 들어 있는지 검사**(자동 조종 한 판에서 404·그려지지 않은 스프라이트 0).
5. 단일 파일판(`build-single.ps1`)은 모든 그림을 넣어야 하므로 분할 로딩과 양립하게(또는 단일 파일판에서는 전부 미리 넣기).

## 3. 소리 지연 (1단계 ①)
- 주제가·효과음은 **시작하기(첫 사용자 동작) 뒤**에 백그라운드로 받는다. 전투 시작은 소리를 기다리지 않는다(없으면 소리 없이 시작, 오면 그때부터).
- 지금 `music.js`·`assets.js`의 소리 불러오기와 iOS 자동재생 제한 처리를 깨지 않게.

## 4. 캐시 규칙 (1단계 ①)
- 그림·소리는 **1년 캐시 + immutable**, HTML·JS·CSS는 지금처럼(새 배포가 바로 반영되게). 방법: `dist_web/_headers`(Cloudflare Workers 정적 자산의 `_headers` 규칙 — 먼저 지원 여부를 공식 문서로 확인하고, 안 되면 7절에 "서버 쪽(index.js)에서 헤더를 붙여야 함"으로 제안만 하고 만들지 않는다).
- 길게 캐시해도 그림을 바꿀 수 있게 **그림·소리 주소에 버전 꼬리표**(`?v=<ASSET_VERSION>`)를 붙인다. `ASSET_VERSION`은 한 곳(`assets.js`)에 두고, 그림을 바꾸면 올린다. `build-single.ps1`의 `__asset()` 표·`sync-dist.ps1`·`check-live.ps1`이 꼬리표 때문에 깨지지 않는지 확인(깨지면 고친다).
- `dist_web/_headers`는 git에 올리는 원본이므로 `.gitignore`와 `sync-dist.ps1`이 지우지 않는지 확인.

## 5. 출동 단추·공지 (1단계 ③)
1. **출동 단추가 스크롤 없이 보이게**: UI 2 모험 탭에서 PC 1280×720·1280×800·태블릿 1024×768·세로 820×1180·768×1024·폰 375×667·360×640 모두. 단계 지도는 위에 그대로 둔다. 방법은 네가 고르되 지금 배치를 크게 바꾸지 않는 쪽을 먼저: 화면 높이가 낮으면 작전 카드의 큰 장면 그림을 줄이거나 숨김 + 단계 마디 크기 한 단계 줄임; 그래도 안 들어가는 폰은 **아래 메뉴 바로 위에 고정된 출동 단추**(지금 단추와 같은 동작). UI 1은 그대로.
2. **공지 1회**: 로비에 들어갈 때 자동으로 뜨는 장 공지는 **계정·기기마다 한 번만**(닫기를 누르면 다시 안 뜸). 머리글의 소식 아이콘(`fn_news`)이 있으면 거기서 다시 볼 수 있게, 없으면 보고서에 적는다.
3. 전·후 캡처: `docs/codex/preview/B_lobby_<크기>.png` 6크기 이상(각 400KB 이하).

## 6. 느린 기기 적 수 상한 — 장치만, 기본 꺼짐 (1단계 ②)
- `main.js` 적 생성에 **동시 적 수 상한** 장치를 넣는다: `renderQuality.level`이 가장 낮은 두 단계일 때만, 상한을 넘는 일반 적 생성은 건너뛴다(대왕·중간 보스·특별한 적은 제외). 값은 한 곳(`SLOW_ENEMY_CAP = {enabled:false, cap:…}`)에 두고 **기본 `enabled:false`**. 꺼져 있을 때 재생 검사 결과가 전과 같아야 한다.
- 켰을 때의 효과를 **재서 표로**: iPad급 ×6·안드로이드급 ×6의 4-3·4-5 합성 군중(기존 `tablet-perf.py --stress`)에서 상한 없음 / 120 / 100 / 80일 때 평균·하위 1% FPS. 어떤 값이면 하위 1% FPS 20 이상인지. **켤지·몇으로 할지는 선생님이 정한다**(밸런스가 바뀌므로). 보고서에 제안만.
