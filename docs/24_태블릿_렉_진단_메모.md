# 태블릿 후반 렉 — 진단 메모 (2026-09-23, 진행 중)

> 상태: **원인 조사 중간에 멈춤(사용량 부족). 코드는 아직 고치지 않았다.** 다음 작업자는 아래 "이어서 할 일"부터 한다.

## 사용자 보고
- 학생들이 패드(태블릿)로 플레이하면 **판 후반으로 갈수록 렉이 심하고 프레임 드랍이 과하다**.

## 측정 도구
- `game/tools/qa/perf.cjs`: 헤드리스 Edge를 태블릿 크기(1180×820, 배율 2, 터치)로 띄운다. 로그인 → 단계 출동 → `__debugPilot`으로 후반까지 빨리 감기 → CPU를 느리게(throttle) 한 채 실제 시간으로 프레임 시간과 CPU 프로필을 잰다.
- 로컬 서버는 `dist_web/`을 서빙한다. `game/`을 고친 뒤 측정하려면 `game\tools\sync-dist.ps1`을 먼저 돌린다.
- 예시:
  ```
  . .\game\tools\env.ps1; Require-Node
  node game\tools\qa\perf.cjs --stage CH01 --diff easy --ff 200 --measure 8 --throttle 4 --label base
  ```
  옵션: `--gpu 1`(GPU 사용), `--dsf 1`(배율 1), `--skills F1,L1,V2,W1`(만렙 스킬 강제), `--extra 120`(적 추가 소환).

- 배율 2일 때 캔버스 픽셀이 4배라 가장 크게 느려진다. 게임 코드 계산(JS) 시간은 전체의 몇 %에 불과했다.

## 코드에서 찾은 의심 원인 (확인 필요)
1. **밀린 계산 몰아 하기**(`main.js loop`): 한 프레임이 늦으면 다음 프레임에 전투 계산을 최대 15번 몰아서 한다. 느린 기기에서는 느릴수록 더 느려진다. 120Hz 아이패드에서는 `Math.round(realDt*60)`이 0 또는 1이라 속도가 흔들릴 수 있다. → 누적 시간 방식 + 프레임당 최대 2~4번 제한 검토. 서버의 판 시간 검사와 맞는지 확인할 것.
2. **화면 전체를 여러 번 칠함**(`main.js draw`): 배경 칠하기, 바닥 무늬, 어둡게 덮기, 색조, 격자선, 비네트(화면 전체 원형 그라데이션을 매 프레임 새로 만듦). 배율 2 태블릿에서 채우기 비용이 크다. → 비네트를 미리 그린 캔버스로 재사용, 불필요한 전체 덧칠 줄이기.
3. **해상도 배율 2 고정**(`main.js resize`): `devicePixelRatio`를 최대 2까지 그대로 쓴다. → 프레임이 계속 느리면 배율을 2 → 1.5 → 1.25 → 1로 낮추는 **자동 화질 조절** 검토.
4. **적·효과 수에 비례하는 그리기**: 적마다 스프라이트·색조·반짝임·체력바, 탄·효과마다 원형 그라데이션을 새로 만들고 'lighter' 합성, 피해 숫자마다 글꼴 지정 + 테두리 글자. 후반에 적(최대 160)·보석(최대 300)·효과가 늘면 함께 늘어난다. → 그라데이션·색조 스프라이트 캐시, 화면 밖은 그리지 않기, 피해 숫자 개수 상한.
5. **매 프레임 HUD 글자 다시 쓰기**(`updateHud`, `sgHud`): 값이 같아도 `textContent`를 매 프레임 다시 넣어 화면 배치를 다시 계산하게 한다. → 값이 바뀔 때만 쓰기.
6. **효과음**(`assets.js playSfx`): 후반에 타격·처치·보석 소리가 몰릴 때 동시 재생 수 제한이 있는지 확인할 것(모바일에서 렉 원인이 되기 쉬움).
7. 적이 160을 넘으면 매 틱 거리순 정렬(`simTick`의 `enemies.sort`), 적끼리·탄과 적 충돌이 전부 대 전부 계산인지 확인할 것.

3. 수정 전후를 같은 명령으로 다시 재고, `node --test "tests/*.test.mjs"`와 `game\tools\qa\sim.ps1`로 게임 결과가 그대로인지 확인한다. 휴대폰 375, 태블릿, PC 1280 캡처도 확인한다.
