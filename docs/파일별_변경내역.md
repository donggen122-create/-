## 이후 수정 시 확인 순서

1. 규칙·비용·조합을 바꾸면 rework-core.js와 element-content.js를 먼저 함께 확인합니다.
2. 피해량이나 파츠 기능을 바꾸면 전투 테스트와 첫 5개 스테이지를 다시 확인합니다.
3. 서버 저장 형식을 바꾸면 기존 v1/v2 프로필, 재시도, 관리자 지급과의 동시 처리도 확인합니다.
4. npm.cmd test 통과 후 npm.cmd run build로 정적 파일을 다시 만듭니다.
5. 운영 배포 전 기존 릴리스와 최신 사용자 변경을 확인하고, 관리자 비밀값·기존 학생 계정·이용권 이력을 보존합니다.

주인공 PNG 27개는 교체 대상이 아닙니다. 새 무기 표현은 별도 리소스와 Canvas 레이어에서 수정합니다. 관리자 열쇠 및 로컬 테스트 설정은 배포·공유 문서에 넣지 않습니다.

## 동시 배포 f330b063 변경을 계승한 파일

아래 항목은 다른 작업에서 추가한 관리자 ID/PW 로그인과 접속 상태 기능을 v2에 함께 반영하기 위한 통합 내역입니다. 최종 통합본의 배포는 이 문서 작성 시점에 대기 중입니다.

| 파일·경로 | 계승하는 변경 | 필요한 이유 |
|---|---|---|
| game/admin/index.html | 아이디·비밀번호 로그인, 토큰 인증, 접속 중인 학생 표시. 기존 이용권 지급·중복 방지·지급 기록 유지 | 최신 관리자 기능과 기존 이용권 정책을 함께 사용 |
| server/src/index.js | /api/admin/login·online, /api/presence, /presence.js 응답, HTML의 injectPresence 처리와 로그인 쿠키 | 관리자 인증과 접속 상태를 서버 기준으로 처리 |
| server/wrangler.toml | [assets]의 run_worker_first = ["/"] 설정 계승 | 첫 페이지 요청이 Worker를 거쳐 접속 신호 스크립트를 삽입할 수 있게 함 |
| server/schema.sql·server/migrations/2026-09-22_presence.sql | 최신 접속 상태 표와 필요한 마이그레이션 계승 | 새 접속 상태 API가 기존 DB 위에서도 동작하도록 표 구조 보존 |
| game/index.html 및 서버의 HTML 응답 | 게임 첫 화면의 /presence.js?v=1 주입 보존 | 학생 페이지가 실제로 접속 신호를 보내 관리자 목록에 연결되게 함 |
| 공개 공유 서버 소스 /share/server/ | 통합된 index.js와 guardian.js·legacy-migration.js·profile-migration-v2.js 및 설정·스키마·관리 화면 | 다음 작업이 최신 관리자 기능과 v2 저장 형식을 함께 이어받게 함 |

공개 최신 main.js·cloud.js는 v1 기준본과 동일함을 대조했습니다. 이번 통합에서는 v2 게임 전투·성장 구현을 유지하고 서버의 접속 신호 삽입을 계승했습니다. 접속 스크립트는 /src/presence.js가 아니라 **/presence.js?v=1**이며, sp_in 로그인 쿠키와 같은 출처의 요청을 사용합니다.

기존에 로그인한 학생도 /api/me 응답에서 접속 신호용 쿠키를 갱신할 수 있게 연결했습니다. 접속 상태 표는 반복 실행 가능한 생성 처리를 함께 두어 이미 운영 중인 DB에서도 기능을 이어갈 수 있게 했습니다.

관리자 화면의 새 입력 선택자는 #aid·#apw, 제출 버튼은 #login-form button[type="submit"]입니다. 화면에는 기존 관리자 열쇠를 입력하는 대체 로그인 칸이 없습니다. 운영의 새 ID/PW가 제공되지 않았으므로 운영 UI 로그인 성공은 미검증입니다. 로컬 시험용 ID/PW 테스트와 기존 열쇠를 이용한 운영 API 검증은 구분하여 최종 배포 기록에 남깁니다.
