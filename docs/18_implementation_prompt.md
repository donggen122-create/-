# 18. 다음 코딩 작업에 전달할 구현 지시 프롬프트

아래 프롬프트를 AI 코딩 도구에 그대로 전달한다. 단계 1(검증판)부터 시작하며, 각 단계 프롬프트는 이전 단계 완료 조건을 전제한다.

---

## 프롬프트 1 — 프로젝트 골격·데이터 파이프라인·검증기

```
너는 브라우저 탑다운 서바이벌 액션 RPG "LUMEN"의 기술 책임자다. 기획서는 docs/ 와 data/ 에 있다. 먼저 docs/14_tech_architecture.md 와 docs/06_combat_spec.md 를 읽어라.

작업:
1. Vite + TypeScript(strict) + PixiJS v8 프로젝트를 생성하고 docs/14 §1의 폴더 구조를 만든다.
2. data/*.csv 와 data/*.json 을 읽어 content.bundle.json 을 생성하는 빌드 스크립트 tools/build-content.ts 를 작성한다. CSV 파서는 따옴표·세미콜론 리스트를 처리한다.
3. tools/validate.ts 에 docs/14 §10 의 테이블별 검증 규칙을 전부 구현한다(ID 패턴, 외래 ID 존재, 수량, 범위, 챕터당 도전 3, 드롭 가중치 합 100 등). 위반 시 파일·행·규칙을 출력하고 종료 코드 1.
4. src/content/types.ts 에 모든 테이블의 TypeScript 타입을 정의하고, 번들 로더가 타입을 반환하게 한다.
5. balance.json 을 새로 만들고 docs/12 의 모든 상수(곡선·상한·비용·드롭·타이밍)를 옮긴다. 코드에 매직 넘버를 두지 않는다.
완료 조건: `npm run content` 가 검증 통과 후 번들을 생성하고, 검증기 단위 테스트(의도적 오류 주입 10건)가 통과한다. 현재 data/ 에서 검증 오류가 나오면 수정 대신 목록을 보고하라.
```

## 프롬프트 2 — 결정적 시뮬 코어

```
docs/06_combat_spec.md, docs/12_formulas_balance.md, docs/14 §2·§3·§7 을 기준으로 렌더와 완전히 분리된 전투 시뮬레이션을 구현한다.

요구:
- 고정 틱 60Hz, 누적 상한 5틱. 시드 스트림 6개(xoshiro128**). 부동소수 결정성을 위해 위치·속도는 정수(1/1000u) 또는 결정적 연산 순서로 구현하고 Math.random/Math.sin 등 비결정 요소를 사용하지 않는다.
- 엔티티 SoA 저장, 2u 공간 해시, 객체 풀.
- 플레이어 이동·충돌(06 §1), 조준 9종(06 §2), 슬롯 6/6, 경험치 곡선·보석·병합·자석(06 §4), 레벨업 후보 생성·가중치·새로고침/제외/잠금/건너뛰기(06 §5), 진화·융합 규칙(06 §6), 피해 수신 순서·무적·넉백·상태 이상 8종·회복 상한(06 §7), 스폰 링·상한·대기열·재배치(06 §8), 일시 정지(06 §9).
- StatSheet: 합연산/곱연산 버킷과 상한(balance.caps), 낭비량 기록.
- 효과 노드 12종 우선: damage, area_damage, apply_status, knockback, spawn_projectile, chain, orbit, beam, spawn_field, spawn_strike, mark, light.
- 스킬 8종(S01,S02,S03,S04,S05,S09,S12,S21)·패시브 8종·진화 8종을 data 에서 로드해 동작.
- 적 behavior chase/dash/ranged/surround, 엘리트 EL01·EL03, 보스 BS01·BS03(패턴·단계·휴식·no_overlap 스케줄러).
- 웨이브: data/waves.csv 의 CH01~05 를 그대로 실행, 시간 모드 3종 계수 적용.
- RunSummary(스킬별 피해·치명타·명중, 받은 피해 원인, 회복 내역, 10초 단위 DPS) 생성.
테스트: Vitest 로 (a) 시드 12개×챕터 5개 골든 해시, (b) XP 곡선 표(06 §4.1) 일치, (c) 카드 가중치 10,000표본 분포 ±3%, (d) 회복 상한·접촉 상한·무적 비중첩 단위 테스트, (e) 보스 패턴 겹침 0. 헤드리스로 CH01 표준 모드를 봇(가장 가까운 보석 방향 이동)으로 완주시켜 결과를 출력하라.
```

## 프롬프트 3 — 렌더·HUD·화면·저장·보상

```
docs/13_ui_ux.md 의 S01~S06, S21, S22 화면과 docs/14 §6·§8 의 보상·저장을 구현한다.

요구:
- Pixi 렌더: 대체 그래픽(색상 도형+라벨), 카메라, 보간, 예고 도형, 어둠 지대 오버레이, 봉화 링, 피해 숫자 80개 상한, 효과 3단계(판정 불변), 06 §11 연출 규칙.
- DOM UI: 로비·챕터 선택·전투 HUD(조이스틱 플로팅/고정, 키보드, 수동 조준 옵션)·레벨업(진화 안내 표시)·일시 정지(백그라운드 자동)·결과(분석 탭·다음 추천 목표 3개·같은 시드 다시)·설정·저장 관리.
- 보상: RewardCalculator(pure) + run_id 멱등 지급, chapters.csv 의 first_clear/repeat/시간 모드 계수, best_mode 차액 지급.
- 저장: IndexedDB 주 저장 + localStorage 메타, schema_version, migrations 배열, 백업 슬롯 3, 내보내기(JSON+SHA-256)/가져오기(검증→미리보기→적용), 저장 실패 배너와 전투 진입 차단.
완료 조건: CH01~05 진입→전투→결과→보상→저장→새로고침 후 유지가 Playwright 테스트로 통과. 저장 데이터 검사 도구(tools/inspect-save.ts) 제공.
```

## 프롬프트 4 — 성장 시스템 (단계 2)

```
docs/09_progression_systems.md 와 docs/11_economy.md 를 기준으로 캐릭터·장비·부품·펫·수집품·특성·프리셋·재화·상점·미션·업적·오프라인·빠른 전투를 구현한다. 모든 능력치는 StatSheet.addStat 으로만 적용되고, 각 아이템 장착 시 스탯 변화가 0 이 아님을 자동 테스트한다. 합성 예시(09 §2.2)·분해 환급 총량 보존·천장 카운터·멱등 op_id 를 테스트한다. 저장 v2 마이그레이션을 추가하고 v1 샘플 100개 무손실을 검증한다. 화면 S07~S13, S15, S16, S18~S20 을 docs/13 의 상태(잠금·빈 목록·재료 부족·저장 실패) 포함으로 구현한다. 경제 시뮬레이터(tools/econ-sim.ts)로 30/60/120분 × 30일을 돌려 docs/11 §4 표와 비교 보고하라.
```

## 프롬프트 5 — 출시 콘텐츠·모드·이벤트 (단계 3)

```
docs/08, docs/10, data/ 전체를 구현 대상으로 한다. 효과 노드 22종·행동 13종·예고 형태 5종·기믹 키 전부를 데이터 구동으로 완성하고, 스킬 24/패시브 18/진화·융합 28/부품 24 동작, 적 40/12, 보스 20+변형, 챕터 6~60(템플릿 생성), 도전 180, 모드 M02~M08, 이벤트 템플릿 6, 교환소 전 테이블, 도감, 칭호를 구현한다. 서버 전용 메뉴(순위·클랜·친구)는 만들지 않는다. 자동 플레이 봇으로 12 빌드 × 60 챕터 클리어율·시간 표를 생성하고, 180 도전 클리어 가능성과 보스 no_overlap 위반 0 을 검증한 뒤 미달 항목을 balance.json 조정 제안과 함께 보고하라. 웨이브 미리보기·보스 패턴 테스트 도구를 제공한다.
```

## 공통 지시
- 기획서와 데이터가 충돌하면 데이터를 우선하고 충돌 목록을 보고한다. 추정치(“설계 추정”)는 실측 후 balance.json 만 수정한다.
- "완료"는 docs/16 의 완료 정의를 따른다. 미구현은 UI에 노출하지 않는다.
- 한국어 UI 문구는 docs/13 의 문구를 사용한다.
